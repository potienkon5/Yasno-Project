# Ясно — развёртывание бесплатной версии без Firebase

## Что сделано

- Полная регистрация: ФИО (отчество необязательно), телефон, роль (мама/папа/опекун/родственник/учитель), имя и фамилия ребёнка, класс, школа и город (необязательные), email, пароль и подтверждение пароля, согласие с политикой.
- Вход по email/паролю, восстановление через email, сессия на новом телефоне.
- Сохранены страницы «Дневник», «Сборы», «Класс», «Ещё», добавление из чата.
- Классы и семьи, права старосты, статусы заданий и сборов — через PostgreSQL RPC и RLS. Реальное обновление через Realtime (плюс обновление при возвращении в приложение).
- PWA для установки в Android, service worker, локальные напоминания, поддержка фонового Web Push через отдельную Edge Function.

**Это исходники, а не готовый APK.** Проверка работы на реальном проекте Supabase и Android-устройствах ещё необходима. Бесплатный тариф имеет лимиты; Supabase может приостановить неактивный проект. Не обещайте 24/7 доступность без контроля.

## 1. Создать проект Supabase

1. Откройте https://supabase.com/dashboard, зарегистрируйтесь и выберите **New project** в бесплатном тарифе.
2. Выберите регион и надёжный пароль базы данных.
3. В разделе **SQL Editor** создайте запрос, вставьте **весь** `schema.sql` и выполните (Run). Для чистой новой базы, не для старой рабочей БД.
4. В **Project Settings → API** найдите Project URL и **anon / publishable key**.
5. В `supabase-config.js` установите `url` и `anonKey`.
6. **НИКОГДА НЕ ВСТАВЛЯЙТЕ service_role или секретный ключ в HTML/JS клиента!**

## 2. Авторизация email + пароль

1. **Authentication → Providers → Email**: включить email/password.
2. Рекомендуется оставить **Confirm email** включённым; это потребует рабочей почтовой доставки. При стандартной встроенной отправке Supabase существуют жёсткие ограничения и ограничения получателей, поэтому для публичного запуска нужна отдельная настройка почтового SMTP-провайдера.
3. Для быстрого теста без писем можно **временно отключить Confirm email**, но не оставляйте это без оценки рисков в публичной системе.
4. В **Authentication → URL Configuration** добавьте HTTPS-адрес опубликованного приложения в **Site URL / Redirect URLs**.
5. Переоткройте приложение, зарегистрируйтесь, войдите, создайте класс. Второй пользователь вводит код класса после регистрации.

## 3. Разместить PWA бесплатно

Вариант: GitHub Pages (публичный репозиторий с исходниками), Cloudflare Pages или другой HTTPS-статический хостинг.

Для Cloudflare Pages: создайте проект, загрузите папку со статическими файлами (`index.html`, `sw.js`, `supabase-config.js`, `manifest.webmanifest`, обе иконки, `privacy.html`). Укажите адрес в Supabase Authentication → URL Configuration. Не публикуйте `schema.sql`, файлы `supabase/functions` с секретами или приватные ключи. Сам `schema.sql` содержит код схемы, не секреты, но его не требуется размещать в Web.

Проверяйте с двух разных телефонов и разных email. `localhost` можно использовать для локальной отладки; для настоящих уведомлений необходим HTTPS.

## 4. Синхронизация по пунктам

1. На телефоне №1 создайте аккаунт, затем класс — появится шестисимвольный код.
2. На телефоне №2 зарегистрируйте другой аккаунт, введите код класса. Оба увидят те же задания и сборы.
3. Если второй аккаунт — другой родитель **того же ребёнка**, после входа в класс в разделе «Ещё» введите восьмисимвольный код семьи, который видит первый родитель.
4. На третьем телефоне можно войти под первым email/паролем: будет тот же аккаунт. Код класса повторно не требуется.
5. Изменения поступают через Supabase Realtime, при возвращении на вкладку выполняется перепроверка. При отсутствии интернета редактирование не очередится и не синхронизируется до успешной отправки; отдельный offline-first слой ещё не реализован.

## 5. Бесплатные уведомления

### Без сервера: уведомления при открытом приложении

В «Ещё» включите уведомления. Во время работы PWA таймер проверяет задачи около 07:30 и 18:00. **Когда браузер/Android выгружает PWA, эти таймеры не выполняются.** Не путать с настоящими фоновыми Push.

### Фоновые Web Push без Firebase (дополнительная серверная настройка)

1. В среде Node.js выполните:
   `npx web-push generate-vapid-keys`
2. Public Key вставьте в `supabase-config.js` → `vapidPublicKey`. Private Key **не публикуйте**.
3. Установите Supabase CLI, авторизуйтесь, привяжите проект и задайте секреты (подставьте ваши значения):

   ```sh
   supabase login
   supabase link --project-ref YOUR_PROJECT_REF
   supabase secrets set YASNO_WEBHOOK_SECRET=LONG_RANDOM_SECRET YASNO_VAPID_PUBLIC=PUBLIC_VAPID_KEY YASNO_VAPID_PRIVATE=PRIVATE_VAPID_KEY
   supabase functions deploy notify --no-verify-jwt
   ```

4. В файле `supabase/functions/notify/index.ts` замените `mailto:admin@example.com` на свою контактную почту и разверните функцию повторно.
5. В **Database → Webhooks** настройте webhook для таблицы `public.class_items`, событие **INSERT**, URL `https://YOUR_PROJECT.supabase.co/functions/v1/notify`, метод POST, заголовок `x-yasno-secret: LONG_RANDOM_SECRET`. Включите webhook и проверьте логи Edge Function.
6. Для утренних/вечерних фоновых напоминаний создайте два Cron-задания (Supabase Cron / pg_cron), которые вызывают ту же функцию POST с заголовком `x-yasno-secret` и JSON-телом. Для Almaty (UTC+5): 07:30 = 02:30 UTC; 18:00 = 13:00 UTC. Тело: `{"mode":"reminder","period":"morning"}` или `{"mode":"reminder","period":"evening"}`. Интерфейс Cron/HTTP настройки и доступность расширения зависят от проекта.
7. Переустановите/обновите PWA, в «Ещё» включите Push, подтвердите разрешение браузера. При смене VAPID-ключей старые подписки потребуется обновить.

**Статус:** исходный серверный код подготовлен, но реальная доставка в фоне зависит от корректного деплоя, Web Push на Android, версии браузера, энергосбережения устройства и тестов. Нельзя считать её гарантированной до испытания на устройствах.

## 6. Установка на Android

Откройте опубликованный HTTPS-сайт в Chrome → меню (⋮) → «Установить приложение» / «Добавить на главный экран». Это PWA, **не APK**. Для сборки отдельного APK можно использовать PWABuilder или Capacitor; при переходе на Capacitor поддержку push нужно тестировать отдельно (вебовые SW не равно нативный Push).

## 7. Безопасность / обязательные действия до публичного запуска

- Заполните `privacy.html` оператором, email, регионом, датой, подготовьте основание для обработки данных детей и согласия родителей согласно применимым законам.
- Проверьте в Supabase Auth лимиты отправки писем, настройку SMTP и подтверждение почты.
- Протестируйте RLS на двух изолированных классах, разграничение старосты, ошибки неверных кодов и попытки доступа к чужим данным.
- Настройте экспорт и резервное копирование: бесплатный тариф не следует считать системой резервного хранения.
- Для полноценного удаления аккаунта нужна защищённая серверная процедура удаления в Supabase Auth; текущая кнопка «Покинуть класс» удаляет только членство, не аккаунт входа.
- В `schema.sql` создание кода класса опирается на случайную генерацию, но короткие коды не заменяют полноценной проверки личности участника. Для открытого публичного сервиса следует предусмотреть приглашения с одобрением администратора и защиту от перебора.

## 8. Проверки

- Регистрация с пустыми полями, неправильным email, разными паролями.
- Login с неправильным паролем; восстановление пароля по email.
- Два телефона и один аккаунт; два разных аккаунта в классе; две семьи.
- Создание задания, домашки и сбора; отметки выполнения; перевод в старосты.
- Попытка создать сбор обычным родителем — должна быть отклонена RPC.
- Попытка оплатить за чужую семью не-старостой — должна быть отклонена RPC.
- Проверка Web Push при открытом/закрытом PWA и отключённом интернете.
