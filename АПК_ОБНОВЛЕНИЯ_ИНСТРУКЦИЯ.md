# Ясно — обновления APK через GitHub Releases

В этой версии исходников обновления скачиваются **в Android-приложении**, а не через PWA.
APK не собран: для сборки нужны Node.js, Android Studio, Android SDK, секретный ключ подписи, настройка Supabase и публичный репозиторий GitHub.

## 1. Настройка приложения

1. В `capacitor/www/supabase-config.js` заполните `url` и `anonKey` своего Supabase. Только **publishable** key, НЕ `secret`/service role.
2. В `capacitor/www/apk-updater.js` замените `REPLACE_WITH_GITHUB_USERNAME` на имя аккаунта GitHub. `GITHUB_REPO` — точное имя публичного репозитория, например `yasno-app`.
3. Исправлять `appId` после установки первой версии **нельзя**. Сейчас он `kz.yasno.classroom`.
4. В Supabase должен быть выполнен `schema.sql` и настроена регистрация Email/Password.

## 2. Создаём Android-проект (Windows PowerShell)

Установите Node.js 20+ (для Capacitor 7), Android Studio и Android SDK. Откройте терминал в папке `capacitor`:

```powershell
npm install
npm run android:add
npm run android:sync
npm run android:open
```

`android:add` выполняют **только один раз**, когда нет папки `android/`.
`android:sync` синхронизирует HTML/JS и автоматически устанавливает нативный плагин `YasnoUpdater` (Java, FileProvider, Manifest, MainActivity).
После редактирования `www/index.html` или `www/apk-updater.js` заново выполняйте `npm run android:sync`.

## 3. Создать первый подписанный APK

В Android Studio: **Build → Generate Signed Bundle / APK → APK**. Создайте keystore и сохраните его отдельно с резервной копией. **ВСЕ обновления должны быть подписаны тем же самым keystore**.

В `capacitor/android/app/build.gradle` проверьте:

```gradle
applicationId "kz.yasno.classroom"
versionCode 1
versionName "1.0.0"
```

Важно: `applicationId` обычно расположен в секции `defaultConfig`; `namespace` должен совпадать с пакетом Java в этих исходниках. Не публикуйте `keystore`, пароли или `key.properties` в публичном GitHub.

Выберите **release** и подпишите APK. Переименуйте выходной файл в `yasno-release.apk`.

## 4. GitHub Releases

1. Репозиторий должен быть **Public**, чтобы GitHub API работал без токена.
2. На странице репозитория откройте **Releases → Draft a new release**.
3. Создайте тег **v1.0.0**, прикрепите **yasno-release.apk**, опубликуйте (не Draft, не Pre-release).
4. Установите APK на два Android-телефона.

**Само наличие APK в репозитории недостаточно:** файл должен быть вложением опубликованного Release.

## 5. Следующий релиз v1.0.1

1. Измените приложение.
2. В `android/app/build.gradle` измените `versionCode 1` на **2**, `versionName "1.0.0"` на **`"1.0.1"`**.
3. Выполните `npm run android:sync`, заново соберите **release APK**, подпишите **тем же ключом**.
4. Опубликуйте GitHub Release с тегом `v1.0.1`, приложив APK с ТОЧНЫМ именем **`yasno-release.apk`**.
5. На телефоне откройте «Ясно» → **Ещё → Обновления Android → Проверить обновления**.
6. Появится кнопка **«Скачать и установить 1.0.1»**. При первом обновлении разрешите «Установку неизвестных приложений» для «Ясно» в Android, затем повторите.
7. Подтвердите установку в системном окне Android. Удалять приложение **не нужно**.

Номер `versionCode` обязан расти с каждым релизом. Название тега `v1.0.1` и `versionName` APK должны совпадать.

## 6. Механизм защиты

- Система читает `/repos/OWNER/REPO/releases/latest` (публичный GitHub API).
- Скачивает только asset с именем `yasno-release.apk` по HTTPS.
- Требует SHA-256, предоставляемый GitHub в `assets[].digest`.
- Повторно вычисляет SHA-256 после скачивания; при несовпадении установка не запускается.
- Проверяет Android package name и возрастание versionCode.
- Android сам проверяет сертификат подписи установленного приложения при обновлении.
- APK остаётся в private cache приложения; системный установщик читает его через FileProvider.
- Пользователь сам разрешает источник установки и подтверждает APK. Тихая установка не предусмотрена.

Если в старой версии APK вообще не было этого нативного плагина, подключить автообновление без установки новой APK-версии **нельзя**: первый APK с модулем ставится один раз вручную.

## 7. Ограничения и проверка

- Это проверка по кнопке и при возвращении в приложение, а не фоновый Android WorkManager. Уведомления о новых версиях при закрытом приложении пока нет.
- Серверные уведомления о домашних заданиях **не решаются** этим модулем; нужен отдельный нативный механизм.
- Если GitHub API недоступен / превышен лимит или `assets[].digest` отсутствует, приложение выдаёт ошибку и блокирует установку.
- Если разные сборки подписаны разными ключами, Android откажет в обновлении поверх установленного приложения.
- В Android-сборке функции установки PWA и Web Push через Service Worker не гарантированы: для производственного APK требуется отдельное тестирование.
- Тестирование реального APK на телефоне и установка обновления в этом окружении не проводились.

### Частые ошибки

**Пишет «Укажите GITHUB_OWNER»** — отредактируйте `www/apk-updater.js`, затем `npm run android:sync` и соберите APK.

**GitHub Release не найден** — у репозитория нет стабильного публичного релиза.

**Сервис не найден** — выполните `npm run android:sync` и убедитесь в `MainActivity.java`, `YasnoUpdaterPlugin.java`.

**Отсутствует SHA-256** — GitHub не предоставил digest; публикацию нужно перепроверить. Обходить проверку не рекомендуется.

**Android сообщает «Приложение не установлено»** — проверьте тот же `applicationId`, ту же подпись и более высокий `versionCode`.

**APK запрашивает разрешение на установку** — разрешите конкретно приложению «Ясно» установку из этого источника; это штатная защита Android.
