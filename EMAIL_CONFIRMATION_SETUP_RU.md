# Настройка подтверждения почты «Ясно» без localhost

## 1. Опубликовать публичную страницу (один раз)
В GitHub откройте репозиторий `potienkon5/Yasno-Project` → **Settings → Pages → Build and deployment → Source: GitHub Actions**.

После объединения изменений на `main` запустите GitHub Actions → **3 - Publish Yasno email confirmation page**, если задача не запустилась автоматически.

Проверьте, что открывается страница:

**https://potienkon5.github.io/Yasno-Project/auth/**

До этой настройки публичная ссылка может выдавать 404.

## 2. Настроить Supabase (обязательно)
Supabase Dashboard → проект `ddwnpqlejvpngciztjsh` → **Authentication → URL Configuration**.

- **Site URL**: `https://potienkon5.github.io/Yasno-Project/auth/`
- **Redirect URLs**: добавьте **точно** `https://potienkon5.github.io/Yasno-Project/auth/`

Сохраните изменения. Для публичного проекта больше не используйте `https://localhost/` в качестве адреса возврата.

### Шаблоны писем
В **Authentication → Email Templates → Confirm signup / Reset password** для стандартных ссылок используйте **`{{ .ConfirmationURL }}`**. Шаблоны, вручную фиксирующие `{{ .SiteURL }}` или `localhost`, могут игнорировать `emailRedirectTo` или `redirectTo`.

## 3. Собрать APK
В **GitHub Actions → 2 - Build and publish signed APK** соберите новую версию с тем же ключом подписи и установите **поверх существующего приложения**. Не удаляйте APK: это сохраняет локальные данные.

## 4. Проверить
1. Зарегистрируйте тестовый email.
2. Откройте письмо с подтверждением.
3. Должна открыться страница GitHub Pages с текстом **«Почта подтверждена»**, а не `https://localhost`.
4. Откройте на телефоне приложение «Ясно» и войдите указанными email и паролем.
5. Если у кого-то осталось старое письмо с localhost, на экране входа укажите email и нажмите **«Отправить письмо подтверждения повторно»**.
6. Для сброса пароля выберите **«Забыли пароль?»**. Письмо откроет ту же HTTPS-страницу с формой смены пароля.

## Важные замечания
- Страница GitHub Pages общедоступна и не требует аккаунта GitHub. Это **не** страница Releases.
- В публичную страницу копируется **только** существующий Supabase URL и публичный anon/publishable key. Не помещайте в репозиторий service-role ключ, секреты GitHub Actions, пароли или токены.
- Ссылка подтверждения одноразовая и может истечь; повторное использование покажет ошибку.
- Если GitHub Pages или Supabase настроены неверно, APK сам исправить перенаправление не сможет.
- Автоматическое открытие приложения после подтверждения потребует настроить Android App Links; текущий сценарий намеренно возвращает пользователя к обычному входу.
