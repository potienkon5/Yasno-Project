# Проверка исправлений «Ясно» для Android

## Приглашения
В Android APK адрес `https://localhost` — внутренний адрес WebView, а не ссылка для приглашения. Теперь при отправке приглашения используется публичная страница установки:
https://github.com/potienkon5/Yasno-Project/releases/latest

Сообщение содержит **код класса** или **код семьи**. Новый родитель устанавливает APK, регистрируется/входит и вводит код в приложении. Это не deep link: автоматически открыть нужный экран через GitHub Releases пока нельзя. Для полноценной ссылки в будущем нужен опубликованный сайт/Universal/App Link.

## Уведомления о сроках
В разделе «Ещё» включите напоминания после обновления APK. Новые записи позволяют выбрать дату и время (по умолчанию 09:00):
- дело — уведомление в дату и время события, если не выполнено;
- домашнее задание — уведомление в дату и время сдачи, если семья не отметила выполнение;
- сбор — уведомление в дату и время срока платежа, если семья не оплатила.

Приложение пересоздаёт локальные напоминания при получении данных с Supabase, входе в класс или возвращении в приложение. Хранятся **до 40 ближайших будущих напоминаний на устройстве**; старые ежедневные напоминания 07:30/18:00 отменяются. Уведомления из Supabase не доставляются при полностью закрытом приложении в реальном времени: для них нужен отдельный удалённый Push.

На Android 12+ для точности расписания может потребоваться разрешение **Будильники и напоминания / Alarms & reminders**, а на Android 13+ — **Уведомления**. При оптимизации батареи производителем время срабатывания может сдвигаться. Нет гарантии, что новые задачи, созданные другим родителем пока приложение не запускалось, попадут в локальное расписание до следующей синхронизации.

## Обновления APK
- В «Ещё → Обновления Android» отображаются GitHub owner/repo, версия встроенных ресурсов и метка модуля обновления.
- Проверка релизов использует GitHub API и SHA-256 из `assets[].digest`, либо `SHA256SUMS.txt`, если поле отсутствует.
- GitHub Actions внедряет в `index.html` номер версии, проверяет, что нужные файлы попали в Android assets, и запускает тест уведомлений.
- В новом APK отключается HTTP-кеш WebView; также при старте выполняется попытка удалить старые Service Worker регистрации и PWA-кеши, не удаляя саму авторизацию.

Для **первой** установки исправления понадобится скачать APK из GitHub Releases и установить поверх предыдущего, с тем же ключом подписи, без удаления данных. Затем создать следующую версию и проверить обновление из приложения. Android всегда требует подтверждения установки.

## Тест
1. Объединить Pull Request, затем собрать новую версию (выше текущей) через Actions; выбрать publish_release.
2. Установить APK **поверх** старой версии.
3. Убедиться в «Ещё → Обновления Android», что появилась строка «Источник APK: potienkon5/Yasno-Project · сборка X.Y.Z · модуль v2». Если нет, вероятно, на устройстве используются старые ресурсы — скриншот этой страницы поможет диагностике.
4. Включить уведомления. Создать дело с датой сегодня и временем через несколько минут, не закрывая проверку; убедиться, что оно отобразилось в расписании.
5. Проверить, что выполненное дело и оплаченный сбор не остаются в расписании после синхронизации.
6. Отправить приглашение в класс: вместо `https://localhost` должна быть ссылка на Releases.
7. Выпустить **следующий** релиз и проверить появление кнопки «Скачать и установить». Не использовать тот же номер версии повторно.

Тесты исходного кода не заменяют проверку на настоящем Android-телефоне.
