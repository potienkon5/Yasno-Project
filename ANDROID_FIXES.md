# Исправления Android-версии «Ясно»

## Что изменено
- Проверка GitHub Releases выполняется при загрузке класса и возвращении в приложение (не чаще одного раза за 5 минут).
- Когда доступен новый релиз, приложение показывает уведомление в интерфейсе. Сам Android не может без согласия пользователя установить APK: нажмите **Ещё → Обновления Android → Скачать и установить**.
- Вместо браузерного Notification API в APK используются **нативные локальные уведомления Capacitor**. Включите их через **Ещё → Напоминания**; будут запланированы ежедневные уведомления на 07:30 и 18:00 по часовому поясу телефона.
- При выключении напоминаний расписание отменяется. Содержимое напоминаний общее, а не персонализированный список заданий.
- Для получения мгновенных уведомлений **при закрытом APK** от других родителей нужен отдельный push-бэкенд/провайдер (это исправление не внедряет удалённый Push).

## Как проверить
1. Создайте новый APK в GitHub Actions, указав версию выше уже установленной, и сохраните тот же ключ подписи.
2. Установите исправленный APK поверх старого **без удаления приложения**.
3. В разделе **Ещё → Напоминания** нажмите «Включить напоминания» и предоставьте разрешение Android.
4. В разделе **Ещё → Обновления Android** нажмите «Проверить обновления»; при наличии нового GitHub Release с файлом `yasno-release.apk` должен появиться пункт скачивания. Для проверки скачивания выпустите *следующую* версию.
5. Для проверки фоновых напоминаний оставьте приложение закрытым до следующего времени 07:30 или 18:00. На некоторых моделях Android энергосбережение и настройки разрешений могут задерживать уведомления.
6. Если Android показывает старую версию, проверьте, что в GitHub Actions был создан **новый** релиз и шаг **Verify updater bundled into Android** прошёл успешно.

## Ограничения
- Без согласия пользователя Android не устанавливает обновления APK. GitHub Releases используется как источник скачивания, установка через системный установщик.
- Нативное локальное уведомление не эквивалентно удалённому Push и не передаёт новые события с сервера, когда приложение закрыто.
- Для подтверждения полной работоспособности требуются сборка GitHub Actions и испытания на настоящем Android-телефоне.
