# Собираем APK полностью через GitHub Actions — без Android Studio

## 1. Загрузите проект в GitHub
Создайте **публичный** репозиторий (например `yasno-app`). Распакуйте ZIP и загрузите **содержимое** распакованной папки, а не ZIP целиком. Папка `.github/workflows` должна оказаться в корне репозитория, а `capacitor` — рядом с ней. Если веб-интерфейс не загружает скрытую `.github`, создайте эти файлы вручную по указанным путям через Add file → Create new file.

**Внимание:** не загружайте реальные секретные ключи Supabase. `sb_publishable_...` допустим в клиенте при включённой RLS; `sb_secret_...` и service_role недопустимы. В `capacitor/www/supabase-config.js` должны быть реальные URL и publishable key. Хранилище Supabase и SQL нужно настроить отдельно.

## 2. Создайте постоянный ключ подписи один раз
В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret**. Добавьте `YASNO_KEYSTORE_PASSWORD` со **случайным сложным паролем** (не менее 20 символов, сохраните его в безопасном месте).

Откройте **Actions → 1 - Create signing key once → Run workflow**. По окончании внизу запуска появится artifact `yasno-signing-key-KEEP-PRIVATE`. Скачайте ZIP. В нём `yasno-release.p12` и `KEYSTORE_BASE64.txt`.

Сохраните `yasno-release.p12` вне GitHub в надёжном месте — если потерять ключ, нельзя будет выпустить совместимое обновление. Откройте `KEYSTORE_BASE64.txt`, скопируйте его одну длинную строку. Добавьте **второй GitHub secret** `YASNO_KEYSTORE_BASE64` с этим значением. НЕ загружайте `p12` в репозиторий, НЕ помещайте пароль в код. После переноса и резервного копирования удалите артефакт и его копии из общедоступных мест. Не меняйте секреты или ключ между выпусками.

## 3. Получите подписанный APK
Откройте **Actions → 2 - Build and publish signed APK → Run workflow**. Для первой сборки введите `version: 1.0.0`, `publish_release: true`. Если GitHub Release публикуется автоматически, получившийся `yasno-release.apk` будет в разделе **Releases** (справа в репозитории). Установите его на Android.

Для пробного запуска без публикации снимите галочку publish_release; APK можно скачать в разделе **Artifacts** запуска GitHub Actions. Но такой APK, если подписан тем же ключом, может быть обновлён будущим релизом.

## 4. Новые версии
Измените файлы в `capacitor/www`, сохраните коммит. Запустите workflow 2 снова с `version: 1.0.1`, `publish_release: true`. Он увеличит Android `versionCode`, подпишет тем же ключом, опубликует `yasno-release.apk` в GitHub Releases. На телефоне откройте **Ясно → Ещё → Обновления Android → Проверить обновления → Скачать и установить**.

Android спросит разрешение на установку приложений из этого источника и подтверждение установки. Приложение **не нужно удалять**. Данные сохраняются при штатном обновлении. Система не поддерживает полностью бесшумную установку.

## 5. Что проверять, если не обновляется
- Репозиторий и GitHub Releases должны быть **публичными**, файл именно `yasno-release.apk`.
- Релиз опубликован (не draft и не prerelease).
- В публикации Releases должен присутствовать GitHub `digest` `sha256:` у APK; модуль откажет в обновлении, если digest отсутствует.
- Android package ID всегда `kz.yasno.classroom`.
- Не меняйте ключ подписи между версиями.
- При обновлении используйте большую версию: 1.0.0 → 1.0.1.
- Проверка кнопки из Android APK; PWA не умеет устанавливать APK самостоятельно.

## Примечание
GitHub Actions на публичных репозиториях обычно бесплатен на стандартных размещённых раннерах в рамках правил GitHub. Репозитории приватного типа и ресурсоёмкие сборки могут иметь ограничения/стоимость. Запуск требует доступности npm, Android SDK и GitHub.

## Безопасность
Не раздавайте пользователям отладочные APK; для распространения используйте только **подписанный release**. Предоставляйте постоянную подпись. Никогда не храните `p12`, пароли или токены с административными правами в публичном коде.
